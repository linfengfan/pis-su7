# 项目画像初始化:探测并固化前端项目约定

探测当前前端项目的结构与约定,经用户确认后写入 `.claude/fe-profile.md`。生成的画像是 分诊子流程(triage) 和 团队子流程(feature-team) 的**唯一项目特定信息来源**——skill 本体保持通用,换仓库只需重跑本命令。

已有画像时重跑 = 增量更新:逐节比对现状,报告过期项,经确认后合并,不盲目覆盖用户手工维护的内容。

---

## 探测清单(逐项执行,查不到的标注"未探测到"而非编造)

### 1. 技术栈识别

- 读 `package.json` 的 `dependencies`/`devDependencies`,识别框架(Vue2/Vue3/React/…)、UI 库、语言(TS/JS)、构建工具(vue-cli/vite/webpack)、测试框架(Jest/Vitest/…)、状态管理(Vuex/Pinia/Redux/…)
- 有 `.nvmrc`/engines 字段 → 记录 Node 版本要求
- 读 CLAUDE.md/AGENTS.md/README(若存在),提取已声明的规范

### 2. 门禁命令(最重要,直接决定准出流程)

从 `package.json` 的 `scripts` 中识别:

| 画像字段 | 识别目标 | 没有时 |
|---------|---------|--------|
| lint 命令 | lint:check / lint(带 --fix 的要标注) | 询问是否需要配置 |
| format 检查 | format:check / prettier --check | 可省略 |
| 测试命令 | test:unit / test | 无测试框架则标注"无自动化测试" |
| 构建命令 | build | 标注构建耗时量级 |
| 单文件格式化 | format:file 类 | 可省略 |

**标注每个命令的耗时量级**(快/中/慢),供 团队子流程(feature-team) 决定哪些必跑、哪些按需。

### 3. 接口层

- 探测 HTTP 封装:搜 `axios`/`fetch` 的统一封装文件(常见 `src/api/`、`src/services/`、`src/request*/`)
- 记录:接口文件清单(或目录)、请求风格(Promise/回调混用?)、响应码约定、错误处理与上报路径、鉴权/加密方式(若有)、环境切换逻辑
- 新增接口的既定模式(找一个近期接口函数作样例)

### 4. 路由与页面组织

- 路由定义位置与注册模式(集中式/模块化、懒加载写法)、路由与页面的目录映射规则
- 新增一个页面的标准步骤(以最近新增的页面为例,写 1-2-3 步)

### 5. 状态管理

- 全局 store 位置、模块划分模式、是否有组合式响应式 store、视图级 store 的惯例
- 判断规则:什么该进全局 store,什么留在视图级

### 6. 公共/高风险区域

- 找出被大量引用的公共组件、工具函数、基类、请求层封装(用引用计数排序,取 Top 5)
- 这些区域改动风险最高,写入画像的"高风险区域"清单

### 7. 参考实现

- 按"复杂页面 / 简单页面 / 表单页 / 列表页"各挑一个近期实现、风格良好的文件作为模板(问用户或按 git log 近期提交挑),记录路径

### 8. 环境与工具

- `.codegraph/` 索引是否存在;知识库是否存在;codegraph 可用性影响检索方式
- 报告输出目录(默认 `fe-reports/`,询问用户是否要进 .gitignore)

## 流程

1. 按探测清单逐项执行(Bash/Read/Grep;有 codegraph 优先)
2. 把探测结果整理为画像草稿,向用户展示**关键决策点**:门禁命令取舍、高风险区域、参考实现选择
3. 用户确认(或修正)后写入 `.claude/fe-profile.md`
4. 提醒用户:该文件**可以进 git**(团队共享同一套约定),后续项目结构变化时重跑本命令增量更新

## 纪律

1. 探测不到的字段标注"未探测到",**禁止用通用常识填充**——画像里每一条都必须有代码依据(注明来源文件)
2. 耗时量级用真实计时,不猜
3. 用户手工补充进画像的内容(如团队口头约定)重跑时**不得删除**
